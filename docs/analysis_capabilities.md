# Analysis capabilities

The repository supplies pinned policy, CAPE overlays, evidence export, and acceptance tooling. A capability is not `Working` until a known-positive completed task produces the expected, hash-covered artifact. Until then, use `Degraded` even when software is installed.

## Safe installation and upgrade

`config/cape.lock.json` is authoritative. Replace every `REQUIRED_BEFORE_EXECUTE` or `RECORD_FROM_DEPLOYED_FILE` value with the SHA-256 of an audited offline archive before executing installation. Rules, signatures, TRiD definitions, and Volatility symbols must never update during a task.

The base host setup now runs the capability installer and validator. The pinned
Volatility Windows symbol pack is about 800 MiB and is downloaded once into
`/srv/winstdt/cache/volatility/`, verified, and copied into the CAPE environment.
Set `VOLATILITY_SYMBOL_ARCHIVE` to an approved local mirror copy to avoid that
download. Suricata rules are copied into an offline snapshot and CAPE uses
`/etc/suricata/winstdt.yaml`; updates require a reviewed lock-file change.

1. Clone CAPE into a new staging directory and check out the locked commit. Do not reset the deployed checkout.
2. Confirm `git status --short` is empty in staging.
3. Audit and hash external data; update the lock file in a reviewed commit.
4. Run `scripts/install-analysis-capabilities.sh` without flags, then with `--execute` against staging.
5. Apply only the overlays under `cape/`; keep runtime data and backups under `/srv/winstdt`.
6. Run `scripts/validate-analysis-capabilities.sh`, unit tests, and all positive/negative acceptance fixtures.
7. Promote the staged checkout only after completed bundles validate. Retain the previous deployment for rollback.

`configure-cape-runtime.sh` checks the exact CAPE revision, reports dirty/untracked state, never resets it, and writes backups below `/srv/winstdt/backups/cape/`.

## Profiles and limits

Profiles are defined in `config/analysis_profiles.json`. `standard` enables CAPA, DIE, TRiD, QEMU screenshots, and Suricata. FLOSS is enabled only by `deep_static` and `full_investigation`. TLS and full-memory collection are opt-in. The full-memory preflight requires 24 GiB free and uses a host lock; raw dumps default to seven-day retention and must not be web-served.

CAPA zero matches means only that the pinned rules did not match. DIE confidence and heuristic language is evidence and must be retained. TLS pinning is reported, never bypassed. Suricata is passive offline PCAP processing and `eve.json` is authoritative.

## Acceptance matrix

Use legal fixtures and retain their expected hashes outside malware directories. Static acceptance needs a CAPA-positive PE, FLOSS stack/decoded string, known DIE result, TRiD result, non-PE negative, timeout, and oversized input. Dynamic acceptance needs a distinctive screenshot window; positive, benign, malformed, and empty PCAPs; controlled HTTPS plus a pinning negative; and the documented Volatility plugin set.

Run:

```text
scripts/validate-analysis-capabilities.sh
python3 -m unittest discover -s tests -v
cargo test
```

The handoff manifest records the requested profile, resolved options, and explicit status for every capability. Completed static capabilities require `analysis/<tool>.json`; all files except the self-referential manifest and hash list are covered by `hashes.sha256`.

## C2 and controlled egress

`scripts/generate-access-events.py` creates clock-corrected `behavior/access_events.json` solely from CAPE/capemon observations and writes `access_events.status.json`. It requires start/end measurements, interpolates offset, checks the analysis window and ETW sidecars, and disables 15-second correlation at uncertainty of 7.5 seconds or greater. It never loads fixture events. The authorized analyzer is pinned from `https://github.com/demistifying/C2-Exfil-E-Rakshak.git`; see `c2_exfil_integration.md`.

```text
git subtree pull --prefix integrations/c2-exfil https://github.com/demistifying/C2-Exfil-E-Rakshak.git <reviewed-commit> --squash
```

Keep adapters outside that subtree and write derived output to `/srv/winstdt/c2-results/{task_id}` so completed handoffs remain immutable.

The Alpine gateway is provisioned by `scripts/setup-egress-gateway.sh`; its
per-run profile is generated by `scripts/configure-egress-gateway.py` and
managed by `scripts/manage-egress-run.sh`. The deployed dual-NIC VM uses
`10.66.0.254` internally and `192.168.125.254` on the non-forwarding
controlled-services network. The private responder provides deterministic DNS,
HTTP, HTTPS, and signed receipts at `192.168.125.10`. Full positive and negative
CAPE lifecycle acceptance remains mandatory. Public egress remains unsupported.

Installed provenance is recorded at `/srv/winstdt/analysis-capabilities.json`.
The deployed versions are CAPA 9.3.1, FLOSS 3.1.1, Suricata 7.0.17 with
52,174 enabled rules, and Volatility 3 2.11.0 with the hash-pinned offline
Windows symbol pack. DIE 3.10 is also pinned and has passed its live PE/text
positive and negative validation. Other statuses remain `Degraded` until completed-task
positive and negative acceptance tests produce hash-covered evidence.
